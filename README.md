# מחברים – אתר תיווך עבודה חינמי מבוסס AI

מעסיקים מפרסמים משרות, מחפשי עבודה נרשמים למאגר. פעם ביום Gemini עובר על כל המעסיקים ומחפש מועמדים מתאימים.
נציג אנושי מאשר כל רשימה לפני שהיא נשלחת למעסיק במייל. כל הפעולות מתועדות ב-LangSmith.

## הרצה

```powershell
cd job-matcher
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env      # ואז למלא את הערכים
.venv\Scripts\uvicorn app.main:app --host 0.0.0.0 --port 8000
```

| כתובת | מה יש שם |
|---|---|
| `/` | דף הבית |
| `/employer` | טופס מעסיק |
| `/seeker` | טופס מחפש עבודה |
| `/manage/<סוג>/<קוד>` | אזור אישי עם כפתור "מחק אותי ממאגר המעסיקים" / "הוצא אותי ממאגר העובדים" |
| `/admin` | ממשק הנציג (סיסמה: `ADMIN_USER` / `ADMIN_PASSWORD`) |

הרצת התאמה ידנית מהטרמינל: `.venv\Scripts\python -m app.matching`

## איך ההתאמה עובדת

1. כל יום בשעה `MATCH_HOUR` (ברירת מחדל 08:00, שעון ישראל) המערכת עוברת על כל המעסיקים.
2. לכל מעסיק נבחרים מחפשי העבודה שבטווח הגילאים שביקש, ושעוד לא הוצגו לו בעבר.
3. Gemini (`gemini-3.5-flash-lite`, מפתח חינמי) מקבל את המשרה ואת המועמדים (בלי טלפון ואימייל) ומחזיר רשימה של מתאימים עם ציון 0–100 והסבר בעברית. רק ציון 60 ומעלה נכנס.
4. **אין התאמה** – המעסיק מקבל מייל "עוד לא נמצאו מועמדים מתאימים". המייל נשלח **פעם אחת בלבד** לכל מעסיק, כדי לחסוך במכסה.
5. **יש התאמה** – נוצרת "הצעה" שממתינה בממשק הנציג. **שום מייל עם מועמדים לא יוצא בלי אישור.**
   הנציג יכול לשלוח את כולם, לסמן מי יישלח, או לדחות. אם השליחה נכשלת, ההצעה נשארת ממתינה.
6. כל עוד יש הצעה שממתינה לנציג, המעסיק הזה מדולג בהרצות הבאות.

## LangSmith

עם `LANGSMITH_TRACING=true` ו-`LANGSMITH_API_KEY` כל הרצה יומית נרשמת כ-trace:
`daily_matching_run` ← `match_employer` ← `gemini_match_batch` (הקריאה ל-Gemini) + `send_email`.
גם החלטת הנציג נרשמת (`human_review_decision`), ונוסף feedback בשם `human_approval_rate` ל-trace של ההתאמה,
כך שאפשר לראות ב-LangSmith כמה מההצעות של ה-AI הנציגים מאשרים.
פרטי המשרות והמועמדים (בלי טלפון ואימייל) כן מופיעים בקריאה ל-Gemini.

## מפתח Gemini חינמי

יוצרים מפתח ב-https://aistudio.google.com/apikey ומדביקים ב-`.env` בשורה `GEMINI_API_KEY=`.
במסלול החינמי יש מגבלת בקשות לדקה וליום, ולכן המערכת ממתינה `GEMINI_CALL_DELAY` שניות בין קריאות
ומנסה שוב אוטומטית כשמתקבלת שגיאת 429 של מגבלה לדקה. כשהמכסה **היומית** נגמרת, ההרצה נעצרת מיד ובממשק הנציג מופיע הסטטוס "מכסת Gemini נגמרה". כל קריאה בודקת עד `MATCH_BATCH_SIZE` מועמדים למעסיק אחד.
שימו לב: במסלול החינמי Google רשאית להשתמש בתוכן הבקשות לשיפור המוצרים שלה.

## מיילים (Google Apps Script)

המיילים נשלחים דרך סקריפט Google Apps Script שמפורסם כ-Web App, מחשבון ה-Gmail שפרסם אותו.
נשלחים שלושה סוגי מיילים: אישור הרשמה (עם קישור לדף האישי), "אין התאמה" (פעם אחת למעסיק), ומועמדים שאושרו על ידי הנציג.

1. ב-https://script.google.com יוצרים פרויקט חדש, מדביקים את הסקריפט וממלאים ב-`SECRET` סיסמה ארוכה ואקראית.
2. מריצים פעם אחת את `doPost` ומאשרים הרשאות.
3. **Deploy** ← **New deployment** ← **Web app**, עם **Execute as: Me** ו-**Who has access: Anyone**.
4. ב-`.env` ממלאים `MAIL_WEBHOOK_URL` (הכתובת שמסתיימת ב-`/exec`) ו-`MAIL_WEBHOOK_SECRET` (אותה סיסמה), ומפעילים מחדש את השרת.

כל שינוי בסקריפט דורש **Manage deployments** ← **New version**. בלי שני המשתנים המערכת עובדת כרגיל, רק בלי מיילים.
מכסה: כ-100 נמענים ביום בחשבון Gmail רגיל, כ-1,500 ב-Google Workspace.

## הערות להעלאה לאוויר

- להריץ עם worker אחד בלבד (התזמון היומי רץ בתוך התהליך).
- להגדיר `BASE_URL` לכתובת האמיתית (נכנס לקישורים במיילים), `SECRET_KEY` ארוך וסיסמת נציג חזקה, ולהריץ מאחורי HTTPS.
- הנתונים נשמרים ב-SQLite בתיקייה `data/` – לגבות אותה.
